# TryHackMe: Hacker Holidays — Расследование инцидента с кейлоггером Packed Light (Writeup)

## 1. Введение и сбор контекста
Расследование началось с анализа комментариев к заданию. Один из пользователей жаловался на аномальное поведение системы: его компьютер постоянно пинговал неизвестный узел по порту `8080`. Для проверки этой гипотезы был предоставлен дамп сетевого трафика в формате `.pcap`.

## 2. Локализация угрозы и обнаружение малвари
Первым шагом была выполнена фильтрация сетевого трафика. Чтобы проверить подозрительную активность, весь дамп был отфильтрован по порту `8080`:

```text
tcp.port == 8080
```

Анализ сетевых пакетов показал четкую хронологию атаки:
1. **Запрос кейлоггера**: Сначала зараженный компьютер обратился к серверу и скачал вредоносный Python-скрипт (HTTP-ответ `200 OK` от сервера `SimpleHTTP/0.6 Python/3.11.2`).
2. **Постоянная активность**: Сразу после загрузки скрипта начался цикличный обмен данными. Компьютер каждую секунду устанавливал новое TCP-соединение и запрашивал одну и за ту же страницу на управляющем сервере (`C2_URL = "http://byte-lotus-hotel.thm"`).

## 3. Анализ вредоносного кода
Изучение тела скачанного Python-файла подтвердило, что это кейлоггер, предназначенный для шпионажа. Скрипт перехватывал нажатия клавиш с помощью библиотеки `pynput` и упаковывал их в HTTP-куку `hotel_sess_state` для скрытной отправки.

Также внутри кода был обнаружен механизм шифрования данных — кастомная функция `xor` и жестко закодированный двухкомпонентный ключ:
* Часть 1: `"H0t3lSt@ff0Nly"`
* Часть 2: `"K3epS3cr3t!"`
* Полный ключ: `H0t3lSt@ff0NlyK3epS3cr3t!`

## 4. Сбор и экстракция данных
Поскольку кейлоггер отправлял каждую нажатую букву отдельно в значении куки, возникла необходимость собрать все данные в один массив. 

Для поиска пакетов, где поле `hotel_sess_state` содержит данные, а не является пустым, был использован фильтр Wireshark:
```text
http.cookie contains "hotel_sess_state=" && !(http.cookie == "hotel_sess_state=")
```

Чтобы автоматизировать процесс и собрать содержимое всех кук «в одну кучу» без ручного копирования сотен пакетов, была применена консольная утилита `tshark`:
```bash
tshark -r traffic.pcap -Y 'http.cookie contains "hotel_sess_state="' -T fields -e http.cookie
```

В результате был получен последовательный список Base64-строк.

## 5. Дешифрование и получение флага
Первая попытка прямого декодирования Base64-строк в текст предсказуемо выдала нечитаемый мусор («кракозябры»). Это подтвердило, что данные перед отправкой были зашифрованы.

Для восстановления исходного текста полученный массив Base64-строк был пропущен через алгоритм дешифрования, использующий оригинальную логику XOR-функции из самого кейлоггера с ключом `H0t3lSt@ff0NlyK3epS3cr3t!`. 

После успешной обработки всех элементов был собран финальный флаг.

**Флаг:** `THM{V3r4_1s_w4tch1ng_0veR_y0u}`
